I want to position the application as a **local-first application**. This means that **user's data and application's core functionality primarily reside on the user's own device instead of depending on cloud to function**.  Here are some pointers thus arrived:

## Immediate availability
I do not want the user to be forced to create an account to use the application. They can use it as soon as they download it. 
The first-launch experience is gracefully simple - 
Welcome -> Get Started -> Workspace Setup -> Application

## Local ownership of Data
I want the user to feel like they own their data. They should be able to export their data and use it in other applications if they want to. This should be a **first-class feature**. I want to think about it right away.
Ideally, user should be able to leave my application without any friction.

## Offline Capability
The application should be **offline-capable** out of the box. User should be able to use the application without internet connection.

## Cloud Backup
Optional, user can opt-in to cloud backup if they want to. They may require an account however to do so. 

Additionally, two important meta principles - 
1. **Transparency** - At every point the user makes a decision - a clear disclosure of how their data is used is presented.
2. **Freedom of choice** - We wouldn't force user into decision that aren't necessary, instead, we will progressively present them as the feature need arises.

For eg. - when the user crosses a mark of 3 projects, or a considerable activity on a single project - we will inform the user about optional cloud backup feature. At the same time, we will disclose how and where that data be stored and will ask for a clear permission from them.
